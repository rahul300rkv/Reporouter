Cursor + MCP: How to Connect MCP Servers to Your Editor

By the Repo Router team·Updated November 17, 2026·6 min read

Cursor can use MCP servers, which means its agent can query documentation or external tools while you code. This guide shows the configuration pattern, using GitMCP as the example server.

NoteEditor menus and file formats change between versions. The pattern below is stable, but check Cursor's own documentation if a menu name differs from what you see.

Step 1: get the server URL

Paste the repository address into Repo Router, select MCP Server, and copy the resulting https://gitmcp.io/owner/repo address.

Step 2: choose where to configure it

Cursor reads MCP settings from a JSON file in one of two places:

  • Project-level: .cursor/mcp.json in your project folder, so the server applies to that project only and can be shared with your team.
  • Global: mcp.json inside the .cursor folder in your home directory, for servers you want everywhere.

You can also open Cursor's settings and look for the MCP or Tools section, which edits the same information.

Step 3: add the server

{
  "mcpServers": {
    "react-docs": {
      "url": "https://gitmcp.io/facebook/react"
    }
  }
}

The key (here react-docs) is a label you choose. Use a descriptive name, because the assistant sees it when deciding which tool to call.

Step 4: verify

  1. Reopen Cursor's MCP settings and look for your server in the list.
  2. Confirm it is enabled and shows its available tools.
  3. Open the agent chat and ask something only the documentation would answer, naming the server explicitly.

Step 5: tell the agent when to use it

Add a short project rule so you do not have to repeat yourself. Cursor supports rule files in .cursor/rules. A single sentence is enough:

When writing code that uses the React library, consult the react-docs MCP
server for current API details before answering.

Troubleshooting

  • Server not listed: check the JSON for a missing comma or quote. A single syntax error invalidates the file.
  • Tools never called: mention the server by name in your prompt, and make sure it is toggled on for the current chat.
  • Local command servers fail to start: confirm Node.js is installed and that npx works in a terminal.
  • Agent feels confused: too many enabled servers add noise. Disable the ones you are not using.

Safety

Only add servers you trust, and prefer read-only ones. Review the MCP security checklist before connecting anything that can write or run commands.
