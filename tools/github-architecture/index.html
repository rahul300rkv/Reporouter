Architecture Evidence

GitHub Architecture Explorer

Repo Router · Updated November 24, 2026 · Public GitHub repositories

Inspect potential file relationships in a public repository and distinguish source evidence from illustrative architecture diagrams.

Repo Router provides this feature inside its existing Repository Explorer. This page explains the task and takes your repository URL to the main tool. It does not claim a separate scanning backend or private-repository access.

Generate a first-party diagram

A valid GitHub URL opens Repo Router’s Architecture Diagram tab and generates a structure visualization directly from GitHub paths. No preexisting GitDiagram diagram is needed. To start with a blank form instead, enter a repository URL on the homepage.

How to use this feature

  1. Enter a public GitHub repository address.
  2. Submit the URL to open a first-party architecture diagram automatically.
  3. Click directory nodes to inspect their GitHub paths. Select Inspect imports to add candidate source relationships from sampled files.

What is actually analyzed?

Repo Router samples a bounded set of supported JavaScript, TypeScript and Python text files and looks for relative import references that resolve to observed repository paths. It links potential relationships back to public GitHub source for inspection. This is a heuristic file-level observation, not a full compiler analysis or a runtime dependency graph.

Architecture versus a directory tree

Directory treeArchitecture evidence
Where files liveWhere some files may reference other files
Folders and namesPotential source relationships
Generally available from repository metadataRequires reading sampled source text
Does not prove execution flowStill does not prove execution flow

How is the architecture diagram generated?

Repo Router’s Architecture Diagram tab now builds a clickable structure visualization locally from the public GitHub file tree, without requiring a stored provider diagram. Its optional Inspect imports action adds dashed edges based on selected relative-import syntax; these links remain candidates rather than proven runtime relationships. GitDiagram remains an optional external destination for AI-generated views, not a dependency.

How to validate a proposed relationship

  1. Follow the source-file link.
  2. Inspect the actual import or reference in context.
  3. Check aliases, conditional imports, build configurations and generated sources.
  4. Document whether the relationship is observed, inferred or unverified.

Important limitations

The evidence scan examines a limited sample, supports only selected source syntax, and may have false positives or missed relationships. Third-party diagrams are optional.

Frequently asked questions

Is the architecture diagram a guaranteed representation of the application's runtime?

No. A directory tree and import evidence cannot establish all runtime calls, deployment topology or data flows.

Can it inspect any programming language?

The first-party architecture evidence checks a bounded selection of JavaScript, TypeScript and Python source files; other languages are not comprehensively parsed.
